Frontend API Refactor & TanStack Query Migration Plan
1. What We Just Changed (API Refactor)
We successfully refactored the frontend's API communication layer to follow Next.js and enterprise best practices. The codebase was previously using Next.js Server Actions ("use server") as general-purpose fetch wrappers to the Express backend, which added unnecessary hop latency and scattered API logic.

🏗️ Architecture Improvements
Created a Dedicated API Layer (src/lib/api/):
Replaced empty stubs and centralized all cross-boundary network calls.
Files created: 
caller.ts
, 
releasing.ts
, 
triage.ts
, 
auth.ts
, 
reports.ts
, and 
index.ts
.
All functions now accept a standard RequestInit parameter to work seamlessly on both the server (via 
getServerHeaders()
) and the client (via SWR/TanStack Query).
Slimmed Down Server Actions:
The 9 existing server action files now act exclusively as Next.js orchestrators.
They call the new lib/api/ wrappers and only handle Next.js-specific duties like revalidatePath("/some-route").
Fixed Cross-Project Type Leaks:
Removed a fragile typeof auth import in 
src/lib/database/auth-client.ts
 that reached directly into the nmmcqueue-backend folder, which breaks monorepo module resolution.
Replaced it with explicit local type-casting in consumers like 
staff-header.tsx
.
🐛 Bugs Squashed
Stale URLs: Fixed broken routes where the frontend was calling legacy Express endpoints (e.g., /clinic/pending instead of /caller/pending, and /clerk/ instead of /releasing/).
Wrong Ports: Removed hardcoded localhost:5000 fallbacks, standardizing on exactly what is in 
.env
 (NEXT_PUBLIC_API_URL pointing to 3001).
2. Next Step: Adding TanStack Query
Our frontend components currently manage API data using scattered useState and useEffect hooks. By migrating to TanStack Query (React Query), we will eliminate boilerplate, gain automatic caching, improve loading UX, and simplify our SSE (Server-Sent Events) integration.

The Objective
Install @tanstack/react-query, set up the global QueryClientProvider, and migrate at least one existing manual fetching hook (like 
use-triage-queue.ts
 or 
use-clerk-queue.ts
) to demonstrate the new pattern.

The Prompt to Execute
"Please install @tanstack/react-query and configure it comprehensively for our project. Once installed:

Set up the Provider: Create src/lib/providers/query-provider.tsx with a standard QueryClient setup and wrap the global layout.
Migrate a hook: Pick src/hooks/use-triage-queue.ts and replace the manual useState/useEffect logic to use useQuery() calling the new 
lib/api/triage.ts
 functions.
Fix SSE: Make sure the SSE listener logic just calls queryClient.invalidateQueries({ queryKey: [...] }) instead of mutating massive state arrays manually.
Let's start with triage as a proof of concept, and verify it all works before migrating the rest.
